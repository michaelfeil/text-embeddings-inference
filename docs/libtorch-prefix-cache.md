# Experimental LibTorch prefix cache

The native backend can retain transformer prefix state between requests. It is disabled by default; enable it after numerical and performance controls for your deployment. The implementation covers the currently supported causal decoder families; support follows the loaded operation's actual attention policy.

## Configuration

| Environment variable | Default | Meaning |
| --- | --- | --- |
| `TEI_TORCH_PREFIX_CACHE_BYTES` | `0` | Charged resident cache budget in bytes; zero disables the manager. |
| `TEI_TORCH_PREFIX_CACHE_MAX_TOKENS` | `8192` | Maximum retained prefix length per entry. |
| `TEI_TORCH_PREFIX_CACHE_ENTRIES` | `64` | Maximum published entries per loaded engine. |

The byte budget must be nonnegative. Token and entry bounds must be positive. Startup reports whether the loaded model and task can use prefix state. Each engine owns its cache; replicas do not share GPU storage.

## Model and operation coverage

| Loaded causal path | Saved state |
| --- | --- |
| Llama, Mistral/Ministral3, Qwen2, Qwen3 dense and Qwen3 MoE | Per-layer keys and values, plus final hidden rows. |
| Gemma3 | Keys and values for full and sliding attention, plus final hidden rows. |
| Gemma4 dense/MoE option-token decisions and sequence classification | Physical KV producers, including shared consumers and local/global layers, plus final hidden rows. |
| Qwen3.5 dense/MoE and text aliases | Full-attention KV, FP32 DeltaNet checkpoints, projected convolution history and final hidden rows. |
| Qwen3-VL | Text KV and final hidden rows, with image layout/content and every rotary axis included in identity. |

Bidirectional encoders and bidirectional decoder modes continue through their existing execution paths. Ordinary Gemma4 embeddings, EmbeddingGemma2 and Qwen3.5's `noncausal_full_attention` decision mode cannot reuse arbitrary prefix states. Existing unsupported task heads remain unsupported; enabling a cache does not change model eligibility.

## Identity, ownership and output behavior

Identity uses prepared token IDs, token types, positions, multimodal rotary axes and image content/layout. The native bridge supplies borrowed host token views for lookup, avoiding a device-to-host token transfer. Rust supplies SHA-256 image identities; native callers without a digest use exact pixel bytes. Retained keys, values, recurrent state and output rows are independently owned snapshots.

Identity distinguishes absent rotary coordinates from explicitly provided coordinates, including all zeros. Qwen3-VL infers its rotary coordinates from token positions when they are absent; explicit zeros choose different attention arithmetic. The earlier identity treated both as zero-valued metadata and incorrectly returned a complete cached result. A failing CPU control reproduces that error; CPU and CUDA controls now verify both transition directions without reusing the incompatible entry. Presence also scopes admission and every lookup shortcut.

Lookup uses an adaptive exact scan with cached64-token, parent-chained XXH3-128 fingerprints. Simple misses and single-candidate hits avoid query hashing. Competing long prefixes use fingerprints to rank candidates and refine partial blocks; the selected complete prefix is verified exactly. A hash collision falls back to the full exact scan, including recurrent checkpoint eligibility. Ordered, non-overlapping image metadata bounds unusable prefixes before token comparison; other native layouts preserve the original comparison order. Readiness is queried only for candidates that can improve the result. Equal-length hits retain the original first valid entry. Fingerprint storage is charged with each resident entry and follows its existing eviction/reader lifetime.

Image-batch execution context is also part of identity for text-only rows. Qwen3-VL's deepstack residual stages affect the whole batch's arithmetic. When all visual rows are already cached, empty feature metadata preserves those stages on real suffix rows without repeating image processing.

Entries are scoped to the loaded model instance and operation. Changing the instance or arithmetic settings, including BLAS workspace limits, cuDNN algorithm controls and SDPA backend/reduction/priority settings, invalidates them. Failed cached work clears the registry. CUDA snapshots can be reused immediately on their producing stream because writes are queued before publication; other streams require their completion event to be ready. Source allocations are retained on the consuming stream. Charged bytes include tensor payloads and saved input metadata. Admission reserves a complete entry before capturing any layers, including recurrent checkpoints. Entries larger than the budget bypass capture. CUDA allocator reservations and temporary execution buffers are separate from this resident budget.

Native engines use an explicitly ordered cache mode: their submission fence covers every snapshot write and result transfer, including when the next call switches streams. This permits reuse of a pending snapshot on the already-ordered consumer and avoids redundant per-snapshot events. The default cache mode for independent C++ callers retains producer/completion checks and never assumes that a host mutex orders GPU work. A genuinely blocked producer control reproduces unnecessary recomputation in the earlier native path; the ordered path reuses all4 tokens with bitwise-equal results, while an independent consumer still bypasses pending state.

Full-request graphs and suffix graphs share the same arithmetic-policy snapshot as resident entries. Their process-local keys include the fixed policy bytes, so a miss cannot replay a shader captured under old settings after resident snapshots are invalidated. A miss forwards the already-read policy to graph fallback rather than querying it again. A controlled policy-dependent model reproduces stale full-graph output in the previous implementation and verifies separate captures after BLAS and cuDNN settings change.

Native engines observe a causal stem twice before capturing it. A fixed 64-slot observation table fingerprints up to the first 64 prepared tokens, operation and image-batch context; collisions can only permit extra capture, never authorize reuse. Clear and namespace changes reset observations. One-off misses retain the existing CUDA graph path when eligible. This policy avoids filling GPU storage with distinct first-token churn; it does not yet establish that capture pays for every changing-tail distribution.

Text requests with no possible resident first-token match observe the bounded stem before allocating full identities and suffix metadata. If no row permits capture, the original graph/eager fallback runs immediately. Mixed batches retain each row's observation decision, preventing a first-seen row from being observed twice when another row permits admission. Borrowed host metadata is validated once, including equality with the original packed token count. A negative control using shorter views backed by valid larger allocations demonstrates that the prior implementation accepted an inconsistent host identity. The revised path rejects it before lookup and clears failed cached state.

A CPU control isolating cache management, with a model returning a fixed tensor, measures2048-token first-token misses at approximately1.0microsecond versus14.3–15.5microseconds previously, across three alternating pairs of20000 calls. Prepared H100 controls retain bitwise output vectors, but GPU miss latency remains variable. Snapshot admission can now publish independent K/V and complete hidden rows from an already warmed full-request graph, without another backbone call or graph capture. The observer retains original forward tensors without changing attention/projection arithmetic. Whole backing storage is charged once; snapshots own a packed slab copied by a batched, bit-preserving row-strided CUDA kernel, with the original copy fallback for unsupported layouts. Cold graphs and recurrent checkpoints retain eager capture. Graph retirement drains publication copies, including after errors.

Three alternating H100/Qwen3 BF16 prepared last-token pairs retain bitwise-equal outputs. The128-token admission p50 ratio is0.948–1.007 versus the warmed uncached graph, down from the earlier1.49–1.55;512-token ratios are1.005–1.017. The2048-token ratios remain1.108–1.133 because remaining graph capacity cannot retain the full state, so admission uses eager capture. These controls exclude service/tokenization/loading/startup timing and do not establish an improvement for every workload. Short/cold/churn/budget qualification and the long-admission regression remain required work.

Startup warmup and model health probes carry an explicit probe operation. LibTorch temporarily bypasses the user prefix cache for these calls and restores the previous mode on success or error. Token values do not determine probe intent, and an existing user entry remains available afterward.

The native probe flag uses atomic loads and exchange. A concurrent CPU inference/probe/clear/statistics regression reproduces a data race with the old plain flag and passes ThreadSanitizer after this change. Probe begin/end still form a caller-owned scope; the serialized Rust backend owns that scope.

Native engine calls serialize host access to model, graph and staging metadata. Submission events order GPU work when callers switch streams, including result staging; a host mutex alone cannot protect queued graph buffers. Readiness drains prior work and publishes its new initialization event. Destruction drains the last submission, and output leases retain their result pool independently. The regression with a blocked producer detects deferred-output corruption in the earlier library and passes with ordering enabled, both with and without prefix caching. Handles must stay alive until all native calls have returned; starting a new call during or after handle destruction remains invalid.

Reinitialization retires the old graphs, prefix cache and decision head after draining submitted work, then derives optional features from the new configuration. Disabling a feature removes it rather than retaining its earlier instance. CPU/CUDA controls reproduce stale enabled features in the earlier library and verify zero cache/graph state and rejected decision requests after disabling them. A blocked GPU producer also verifies that reload waits, old result leases survive reload and the next inference, and another stream observes completed initialization. The two-slot result pool requires collecting the previous A result before submitting the next A request.

Concurrent waits on the same live output lease use an atomic completion flag. GPU-backed host ThreadSanitizer controls reproduce two racing writes in the earlier flag and pass after this change; Torch and CUDA libraries are uninstrumented. Native stream controls cover embeddings and multi-label classification with cache off/on, one-entry eviction,96 alternating submissions per mode, completion on another CPU thread, cancellation, cache clear while another lease is outstanding, and recovery from an undersized output buffer on another stream. Genuinely pending controls also cover exact snapshot reuse, reload and retirement. Lease/engine destruction still requires caller-owned lifetime discipline.

Decoder sequence classifiers use one packed selector for contiguous CUDA BF16, FP16 and FP32 rows with device INT64 IDs and INT32 boundaries. It copies the last non-PAD row, falls back to the first row for all-PAD sequences, and selects the packed end when no PAD configuration exists. The trained head still receives the original batch/hidden geometry. Other input layouts use the existing selector, including valid INT32 token IDs without PAD configuration. Raw16/32-bit oracle controls cover widths16/129/896/1024/2048, changing IDs, interior/trailing/all PAD and absent PAD configuration. A traced negative control shows the earlier generic padding sequence blocking a classification graph launch under Compute Sanitizer until the producer watchdog opens; the packed selector passes the genuinely pending control with its original2-second watchdog and unchanged pending assertions.

The manager preserves original logical offsets. Pooling, repeated/mixed output selectors, raw token outputs and trained heads receive restored full hidden rows. With complete snapshots, an exact match of every sequence and the original offsets, maximum sequence length and compact token count bypasses the backbone. Hidden-state operations return fresh copies of saved full outputs. Qualified sequence classifiers run their original trained head on the saved full rows: decoder padding selection and Gemma's complete-token scoring and softcap order stay unchanged. Readout results own storage independently of the snapshots. An optional model readout that returns no result falls back to suffix execution. Source allocations remain retained on the consuming stream. Other hits recompute at least the final query token. Checkpoint-only operations retain suffix execution. Qwen3.5 admits sparse, aligned recurrent endpoints; a token match alone cannot create a missing checkpoint.

CUDA prefix readers currently require the same packed offsets, maximum sequence length and compact token count as the request that produced them. Selecting the current GEMM recipe for suffix rows cannot repair cached rows produced by another recipe. A learned Skywork classifier control that first retains32 tokens, then grows to128/512, reproduces logit differences of0.015625/0.0390625 in the earlier library. Geometry filtering fixes that control, including subsequent exact repeats. Geometry also participates in resident duplicate detection and replacement, allowing the same token identity to retain separately qualified shapes. Fingerprint shortcuts, tie selection and collision fallback all honor this filter before querying readiness. CPU partial reuse retains its existing path; cross-geometry CUDA reuse remains a qualification and optimization gap.

The cache uses the original logical GEMM geometry to choose supported MLP output-projection recipes while executing only real suffix rows. This removed measured Qwen3 rounding differences caused by suffix geometry. Plans use a bounded LRU, honor reduction and SM settings, and keep scratch workspace owned by ATen's current stream. CPU execution and unsupported native recipes retain the existing operator path. This does not guarantee identical reduction order across every family and BLAS provider; learned numerical qualification covers each family, dtype and operation separately.

Planning uses the original provider's workspace allowance, which can differ from default cuBLASLt scratch. Valid suffix recipes exceeding that default use temporary ATen storage bounded by the original provider allowance. The measured Gemma2048 router needed only231 bytes beyond the default1MiB; falling back at that boundary changed its reductions. Temporary scratch remains separate from charged resident entries and follows CUDA stream lifetime.

Cold capture keeps the original input buffers and sequence-length bound. A real hit packs only the suffix; a single sequence uses token/position/type views and returns its restored output without another concatenation. Publication events are created only when admitting snapshots.

Ordinary decoder output and gate/up projections use the planner for reused suffixes. Gemma and Qwen3.5 also preserve ordinary text/input/gate/router projection geometry while retaining existing Radix recipes. The registered Gemma4 FP32 expert router uses the shared planner. Cold capture and existing dynamic FP8 providers remain unchanged.

## Combining persistence with RadixMLP

The manager derives uncached compact/unfold maps from the original full-context Radix mapping. It does not rebuild a tree from isolated suffix tokens. Equal suffixes with different parent histories remain distinct. Prefix hits skip layer computation for cached tokens; RadixMLP can still share token-local work on uncached branches.

Suffix attention uses independent query/key cumulative arrays and a causal mask that includes the prefix offset. Prepared logical positions and API token usage retain their original meaning.

For default Torch global attention with head64 or head128, a single remaining query uses a separate native specialization with Torch's unfused softmax arithmetic and no single-query GQA layout swap. Longer and windowed suffixes retain their existing attention provider. Matched-operand controls compare the final query against original full-context execution. Across96 reproducible head128 inputs, BF16 matches bitwise; five FP16 cases differ by one representable output step. The FP16 regression includes that rounding-boundary input and bounds the difference to one step rather than claiming universal bitwise equivalence. Random-input controls found rounding differences for broader uses of this specialization, so they are excluded from its dispatch contract.

## Current execution limits

[Native cache design references](libtorch-cache-references.md) compare mistral.rs, SGLang, llama.cpp and FlashInfer and describe the C++ ownership boundary and next integration steps.

The implementation assembles contiguous prefix/suffix KV rather than using paged attention. Sliding-window layers currently retain the whole admitted prefix and apply the original window mask. Cold capture remains eager. Eligible non-recurrent suffixes can use CUDA graphs keyed by original/suffix geometry, model namespace and math policy. Replays bind matched parent state into owned graph buffers and copy it when the immutable parent changes, so the shader can rebind without retaining its owner. Graph publication batches copies into one owned resident buffer per snapshot; tensor views keep its layers and hidden output alive. Input copies are grouped by device/dtype to preserve the fast foreach route. The graph input/state buffers count against the existing graph budget, with a lower-bound rejection before known oversized prefix arenas allocate/capture. Non-admitted misses and capacity bypasses retain eligible full-request graphs; exact hidden-state repeats can return saved results without backbone execution. Recurrent suffix graphs and paged storage remain outstanding.

Suffix graphs remember the last copied immutable parent using a weak reference. Replays using that same live snapshot skip prefix-buffer copies; changed or expired parents copy again. The graph owns its execution buffers, so weak references do not keep resident snapshots alive after clear or eviction. A binding is invalidated before replacement copies and published only after those copies succeed.

Graph warmup allocates full K/V arenas and initializes their prefixes once. Parent views then point into those arenas, so replay copies only suffix rows instead of concatenating full K/V at every layer. Parent replacement updates the arena's prefix views before replay. Retired warmup allocations are retained on the capture stream; full arena storage is charged once, independently of its prefix aliases. Snapshot publication remains independently owned. Graph lookup describes matched spans directly without constructing temporary tensor views.

Graph keys now serialize typed metadata directly into a process-local byte string. Variable-sized fields carry their lengths; operation, model namespace, device, dtypes, arithmetic policy, original/suffix geometry, media, Radix maps and retained state shapes remain part of identity. This removes repeated stream formatting without weakening graph compatibility. Rebinding a changed parent copies the target's leading row count directly from the immutable source, avoiding temporary source views. The copy kernel validates every span before submission; unsupported layouts use the existing typed copy route.

Multi-sequence CUDA INT64 requests gather suffix IDs, positions and token types into three views of one owned allocation. One kernel handles up to64 sequences per launch, preserving sequence order and exact integer bits. All boundaries and retained lengths are checked before GPU work. Single-sequence requests keep their zero-copy slices; CPU and unsupported layouts retain their existing packing. The native submission fence covers these reads and writes along with graph replay and result staging.

The fused BF16 head128 attention adapter uses a16-query, one-warp tile for a single causal suffix query on SM90 and a32-query, two-warp tile for2–32 suffix queries. It retains the original64-key reduction blocks and fused softmax; full requests, other dtypes, other architectures and other attention policies retain their existing dispatch. Single-query controls compare128 final-query vectors across32 seeded ragged/GQA batches against original full-context execution, bitwise. The short-query control adds32 seeded batches with2/7/8/16/24/32 queries, contexts16–2048 and GQA ratios2/8; every compared attention value matches bitwise. Kernel-filtered CUDA memory and synchronization checks pass; a race check samples four launches of the new tile with no hazards.

The suffix shader fixture repeats and changes complete parent identities, survives resident-cache clear, verifies independent output storage, and rejects a known oversized arena before capture. Three alternating cache-off/on learned Qwen3 BF16 changing-tail runs measure p50 ranges of1.56-1.57ms versus1.59-1.60ms at128 tokens,1.92-1.94ms versus2.45-2.49ms at512, and3.83-3.91ms versus6.85-6.88ms at2048. The32-token no-admission case is0.1-0.8% slower in these runs. All compared output vectors match bitwise. Each shape has200 measured calls after30 discarded calls, on a shared H100. These scoped improvements do not establish the requested Pareto improvement for all workloads. Timing covers prepared native inference, excluding HTTP/tokenization/loading, and is scoped to the recorded evidence revision.

A separate fresh cache-off/on pair for the learned Skywork Qwen3 scalar classifier matches every compared changing-tail score bitwise at32/128/512/2048 tokens. Its512/2048 p50 measures2.01/4.00ms versus2.57/6.97ms. This extends numerical coverage to a trained head; one pair does not establish stable performance across classifiers, dtypes or request distributions.

The complete-classifier readout and geometry filter have separate learned controls. Three alternating cache-off/on exact-repeat pairs, preserving the earlier shapes' resident entries as requests grow from32 to2048 tokens, match all compared logits bitwise. Repeated classification p50 is approximately0.2ms versus1.5–6.9ms without caching; each shape has200 measured calls after30 discarded calls on the shared H100. Ragged learned batches, reordered/repeated selectors, padded and all-pad rows, exact repeats and changed tails also match every retained cold/warm score. Native CPU/CUDA fixtures check multi-label padding, independent caller mutations and geometry changes. These controls cover prepared native inference and the recorded checkpoint; cold/admission latency and broader family/provider/dtype distributions remain separate gates.

Separate learned exact-repeat controls for Qwen2 BF16/FP16 and the Gemma4 publisher classifier also match every compared score at32/128/512/2048. These use20 measured calls after5 discarded calls, one fresh cache-off/on pair per checkpoint/dtype. They qualify the tested readout outputs, including the existing Qwen2 packed selector and Gemma's all-token score/cap order; they do not establish stable family-wide latency gains. The native publisher fixture also checks complete cached readout with a distinguishing softcap.

Production readiness remains unproven. Required work includes paired cold/hot/churn/changing-tail and mixed-batch controls with eager and graph baselines; classifier, decision, recurrent and media workloads; budget pressure and sustained eviction; cancellation, error recovery and cross-stream/concurrent native callers. Improvements on exact repeats do not establish a Pareto improvement over those other workloads. The cache-manager stress test covers concurrent CPU inference, clear and statistics, while CUDA controls cover pending publication and cross-stream clear/allocation reuse; these tests do not prove every native engine access is race-free.

Optional cuDNN execution keeps the original packed query geometry and causal provider. Cached query rows use discarded zero placeholders; only real suffix rows are returned. This repeats full attention work, while QKV and MLP computation still skip the prefix. Dense suffix attention with an explicit bias was mathematically equivalent but changed trained logits, so it is not used. Matched-operand single/mixed-batch controls and learned Qwen2 classification/last/mean controls match exactly at the tested lengths. The replay buffers are temporary execution storage, separate from the resident cache budget.

Gemma4 image support continues to follow the existing vision implementation. Checkpoints requiring clipped vision linears remain unsupported before cache lookup; enabling persistence does not override their model configuration.

Functional CPU/CUDA controls are necessary but do not establish learned-model equivalence. Qualification also compares cache-off, cold fill and warm/partial reuse on real checkpoints, including full vectors and trained logits. Timing evidence must distinguish backend inference from HTTP/tokenization, and short-prefix or churn regressions require separate attention. Production deployments should qualify their actual model, provider and request distribution before enabling the cache.

## Short shared prefix qualification

Short query/document prefixes are a primary workload for the next cache design. A prepared H100/Qwen3 BF16 causal-scoring control uses changing documents after8/16/32 shared tokens, batches1/8/32 and1/32 distinct queries. Matching controls use a4GiB graph budget and up to8GiB resident budget, rather than the production512MiB graph default. Providers are warmed by explicit probes; primed controls seed each query/document batch twice before timing. Loading, startup, tokenization and HTTP are excluded. Two opposite-order rounds retain every compared score bitwise.

Natural admission produces no hits for these small prefixes. Primed controls verify that they are reusable, but current overhead remains too high. The initial32-request/32-token/16-shared-token batch took6.75–6.82ms cached versus3.07–3.09ms uncached. Strided copies made the suffix graph contain2139 operations, including896 separate memory copies. Batching those transfers reduces it to375 operations. Packed K/V and hidden arenas remove concatenations, reducing it to287 operations; the same cached batch now takes3.12–3.14ms versus3.03–3.06ms uncached. Eight-token hits remain slower in the measured cases. This is progress in restoration cost, not a claim that short hits improve model latency yet.

The32-query attention tile now improves the primed32-request/32-token/16-shared-token control to2.89–2.93ms versus3.04–3.12ms with the preceding library and3.06ms uncached. Two opposite-order rounds match every trained score bitwise. Eight-token prefixes in the same batch improve to3.37–3.39ms from3.57–3.61ms, but uncached inference is still2.97–3.07ms. Single-request eight-token hits remain around1.57–1.58ms versus1.36–1.37ms uncached. These are60 prepared native calls after10 discarded, under the matched4GiB graph budget; the smaller tile does not establish a gain for every small hit.

Separate opposite-order controls with32 suffix queries after512/2048-token contexts also retain every compared trained score bitwise. Compared with the preceding library,512-token latency falls about6% for a single request and2–3% for eight requests. The2048-token single-request result varies from1.2% slower to2.4% faster, so it establishes no stable kernel latency gain. Total cached inference remains faster than uncached inference in these long-prefix controls; they do not qualify every context or the default graph budget.

A separate eight-token-stem admission experiment detects naturally shared short prefixes and avoids duplicate snapshots within a batch. Its16-token case gains roughly7–11% over uncached inference, but eight-token cases and many-query distributions still regress. The experiment is retained in qualification evidence and is not included in this branch. An immutable cumulative-offset buffer experiment also failed to establish a useful latency gain and is excluded. The GPU trace shows nearly unchanged projection cost for24 versus32 token rows on the tested single-request workload, alongside state-copy overhead. Reduced token arithmetic must translate into lower complete inference latency before these paths qualify.

The latest host changes address measured preparation costs. Under temporary profiler instrumentation, the32-request/eight-token-hit graph key falls from0.52ms to0.12ms and suffix preparation from0.52ms to0.17ms. These instrumented durations diagnose overhead rather than measure production latency. Separate uninstrumented opposite-order controls match every compared trained score bitwise: primed16-token hits take2.45–2.48ms versus3.03ms uncached, and eight-token hits take2.87–2.88ms versus3.05–3.06ms uncached. Switching among32 queries with eight128-token documents and32 shared tokens improves from3.19–3.20ms before direct parent-span copying to2.95–3.00ms, while uncached remains2.90–2.92ms. The many-query case and single-request eight-token hits still do not establish a gain. These controls retain the matched4GiB graph budget,60 measured calls and10 discarded calls. Natural short-stem admission remains outstanding. Retesting its prototype with the host changes restores batched8/16-token gains, but single-request and many-query regressions still prevent adoption.

The next work must admit short shared stems without continually capturing unrelated tails, share immutable block storage across related requests, index many resident prefixes cheaply, and measure the complete execution cost before using a hit. Recurrent and media boundaries remain component-specific.
